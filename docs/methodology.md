# 方法论与评估规范

## 1. 核心恒等式

设 `π(x)` 为号码 `x` 在真实开奖中的边际出现概率，`q(x)` 为某策略选中 `x` 的概率。一次开奖抽出 `k` 个号码（号码池大小 `N`）时，期望命中数为：

```
E[命中数] = Σ_x π(x) · q(x)
```

若开奖是均匀的，即 `π(x) ≡ k/N`，则对**任意**选号分布 `q`：

```
E = (k/N) · Σ_x q(x) = (k/N) · k = k²/N
```

因为 `Σ_x q(x) = k` 恒成立（每注固定选 k 个不同号码），所以：

- 任何策略都不能提高期望命中；
- 任何策略也**不会降低**期望命中；
- 「冷热号」「遗漏回补」「重号邻号」等只在 `π` 偏离均匀时才可能有用，而实测 `π` 与均匀不可区分。

这条恒等式是本项目的判据：不需要相信任何回测的单个数值，只要 `π≈k/N`，结论就是解析成立的。

## 3. v5.4 策略结构

```
data = Fisher-Yates 严格均匀无放回抽样
     + 自标定 P2~P98 结构软约束（和值 / 奇偶个数 / AC 值 / ≥2 分区）
```

- 结构窗口只用评测期之前的历史标定，随新数据滚动，属于样本外安全的做法。
- 结构约束通过「多次候选取违规项最少」实现，不改变抽样分布的期望，只让生成号码的**形态**贴近真实开奖。
- 三彩种最新期均落在 `P2~P98` 带内，近 30 期覆盖率 SSQ/DLT/QXC = `100% / 96.7% / 100%`。
- 分区约束是「≥2 区」而非「硬 3 区」：真实 SSQ 仅约 90% 覆盖 3 区，DLT 约 83.3%。

`smart`（综合智能）是传统频率/遗漏加权路线的唯一保留代表，仅作对照，回测与随机不可区分。

## 4. 评估策略的强制规范

这些是踩过坑之后固化的规则，改动回测代码时不要推翻：

1. **必须带同构合成均匀数据对照组**。没有对照组时，测试框架自身的偏差会被误读成市场信号。
2. **必须逐期配对**求差值，再多次重复求 `z`。不要「每期独立抽样」后比较两组均值，那会放大方差、掩盖真实差异。
3. `random` 基线必须用 **Fisher-Yates 无放回**。`sort(() => Math.random() - 0.5)` 是有偏的，会低估基线，制造虚假增益。
4. 频率/冷热方向必须做**样本外**验证：前半段估 `π`，后半段评测，不能样本内自证。
5. 单次门禁 `|z|>2` **必须独立复跑 3 次**确认。噪声越界的符号会在复跑间随机翻转、幅度回落；真实信号不会。
6. 40 轮高功效验证也会偶发 `|z|>2`，真实数据与合成对照都会出现。判定以理论 `E` 恒等式 + 多轮符号/幅度趋势为准，不以单次为准。

## 5. 多重比较校正

一次实验同时检验 `m` 个变体时，至少一个假阳性的概率约为 `1-(1-α)^m`。`m=4, α=0.05` 时约 18.5%——这正是「偶发越界」的来源。

`tests/multiple_testing.js` 用**固定种子**（可复现，CI 不会随机变红）重跑一轮严格样本外逐期配对实验，得到 4 个变体的 `z` 与双侧 `p`，再做：

- **Bonferroni**：阈值 `α/m = 0.0125`，对应 `|z| ≥ 2.498`
- **Benjamini-Hochberg FDR**：按 `p` 排序，找最大 `k` 使 `p(k) ≤ k/m · α`

两者校正后显著项均为 0，与理论恒等式一致。这个脚本是对「单次 `|z|>2` 是噪声」的独立佐证。

## 6. 数据真实性校验

`scripts/validate_data.py`：号码范围/个数/重复、期号唯一递减、`lottery_data.js` 时间戳与头注释一致、raw / js / HTML 内联三源前 50 期一致。CI 每次 push 都会在 Python 3.10~3.13 上跑。

## 7. 不做什么

不采用 LSTM / 深度学习 / 数论装饰 / 玄学权重。它们在 `π≈k/N` 的前提下没有可提取的信号，样本内表现全部来自过拟合。本项目保留它们的历史对照代码，只是为了能复现「为什么不行」。

## 8. 随机性检验套件（2026-11-16 合并）

借鉴 GitHub 上 `dj-on-github/sp800_22_tests`（175★）与 `stevenang/randomness_testsuite`（197★）的 NIST SP 800-22 Rev1a 实现，`tests/randomness_suite.js` 选取不依赖百万比特长序列的 5 项检验：

| 检验 | 检出什么 |
| --- | --- |
| monobit 单比特频率 | 0/1 整体偏倚 |
| runs 游程 | 相邻位交替过于频繁或过少（序列相关） |
| block-frequency 块内频率 | 局部区间偏倚 |
| cumulative-sums 累计和 | 随机游走单向漂移（趋势） |
| serial 序列模式 (m=3) | 短模式重复（周期性） |

**位流构造的取舍**：33 个红球的奇偶天然是 17:16，直接二值化会制造「有偏」假警报。因此选用天然对半分的字段：QXC 前 6 位 `0~9 → (d>=5)`、SSQ 蓝球 `1~16 → (blue>=9)`。判定沿用 NIST 的 `p >= 0.01`，真实组另做 Bonferroni / BH-FDR 校正。

**灵敏度验证（借鉴 NIST README 的关键做法）**：只证明「真实数据全部通过」是不够的——检验太弱也会全部通过。所以套件同时喂入四组数据：

| 数据集 | 期望结果 | 实测 |
| --- | --- | --- |
| 真实 QXC 开奖 | 校正后无显著项 | 0/5 显著，Bonferroni 与 BH-FDR 均为 0 |
| 同构合成均匀对照 | 无显著项（检查检验框架自身无偏） | 0/5 |
| 已知偏倚 `P(1)=0.60` | 能检出 | 5/5 显著 |
| 已知序列相关（70% 沿用上一位） | 能检出 | 3/5 显著 |

固定种子 `20261116`，CI 结果可复现。跨彩种另复核 SSQ 蓝球 monobit/runs 与 DLT 后区组合均匀性 χ²（含合成对照），全部通过。

**未采用**的 NIST 检验：binary matrix rank、DFT、linear complexity、Maurer universal、random excursion。它们要求 10⁶ 量级比特流与特定渐近分布，彩票样本量（最多约 5500 bits）不足，硬套只会得到不可靠的 p 值。

## 9. 一个真实踩过的坑：数据展示顺序

`data/raw_dlt.json` 的 1200 期后区号码**全部按升序存放**（升序 1200 / 降序 0）。若把两个后区号码直接拼接成位流，同期位模式 `(0,1)` 出现 667 次而 `(1,0)` 为 0，runs 检验必然报「显著序列相关」——这是**展示格式造成的伪结构**，不是开奖缺陷。

处理方式：DLT 后区改用**无序两号组合**的 χ² 均匀性检验（`C(12,2)=66` 种，df=65），完全不依赖顺序；并配一组同构合成对照。

教训：做序列检验前必须确认「顺序」是物理摇奖顺序还是数据整理顺序。把人为排序当成时间结构，是最容易制造假阳性的一类错误。同理，本期数据在 `raw_*.json` 中最新在前，做时间序列分析前需先反转。
